# Pinkbox — архитектура клавиатурного инструмента

Редакция 13 октября 2026, основание — текущий SPEC и согласованный сценарий: один живой голос, пять независимых четырёхтактовых записей. Прежняя архитектура генератора и по одному clip на роль заменена; история — в Git.

## Модули

- `patterns.js`: диатонические ступени natural minor/major, трезвучия/7/9, чёрные мажорные аккорды, arpIndex, клавиатурные привязки, проверка loop-событий. Музыкальные данные без Tone/DOM.
- `state.js`: PerformanceState, held-input stack, последний выбранный живой голос, параметры гармонии/звука, REC/open note capture, пять слотов, pending BPM/mute, поколение сессии. Чистая проверяемая модель.
- `audio.js`: один Tone Context/Transport, шесть фиксированных каналов, исполнение нот на callback time, сглаживание громкости/FILTER, создание/очистка сессий, безопасный STOP.
- `ui.js`: постоянный DOM, клавиши ноутбука через code, pointer capture на клавишах/пэдах/ручках, native sliders/selects, пять дорожек и их параметры. Убирает свои слушатели при disposal.
- `main.js`: сборка controller/UI, visibility/pagehide. В фоне STOP сохраняет clips, отменяет held-input и кандидат.
- `build.js`, `server.js`, `scripts/build.js`: сохранённый Bun/Tone browser bundle workaround, сервер разработки и статичный dist.

## Музыкальная модель

Белая позиция задаёт номер ступени; tonic/scale определяют MIDI-ноту. Аккорд берётся через интервалы ступеней 0/2/4 и дополнительно 6/8. Чёрная позиция берёт корень предыдущей белой +1 semitone и строит major 0/4/7. Диапазон исходно вокруг MIDI 60; BASS опускает корень на две октавы.

Held-input хранится по источнику: физический code, pointer id или keyboard activation экранной кнопки. Auto-repeat игнорируется, последнее удерживаемое положение выигрывает, при отпускании восстанавливается предыдущее. LINK бас читает keyboard positions, MANUAL — pads. Это маршрутизация одного голоса, не одновременные независимые бас/аккорды.

Live signature включает положение, состав нот, ARP/direction и тембр. Изменение освобождает прежние live-ноты и атакует новые на следующем шаге. FILTER сглаживается отдельно и не перезапускает ноты. ARP считает выбранный порядок UP/DOWN/UPDOWN с периодами 4/2/1 шаг. Переход к ARP прекращает удерживаемый аккорд. При выходе из ARP снова атакуется целый аккорд. Больше одного live источника нет.

## Единый clock

PPQ 192, шаг 48 ticks (1/16), такт 16 шагов, цикл REC/loop 64 шага. Один scheduleRepeat обслуживает всё. Номер шага берётся из getTicksAtTime(callbackTime), ноты атакуются/освобождаются с этим callbackTime. Live-input квантован на ближайший ещё не запланированный шаг; это упрощает точную запись и может дать задержку до одного шестнадцатого шага плюс lookahead (40 ms, updateInterval 10 ms).

BPM 60–160 применяется на ближайшем доступном начале такта. Durations остаются в шагах, поэтому note-off и длина REC следуют темпу, а pitch не меняется. Mute loop также происходит на начале такта без сброса origin; unmute возвращает общую фазу. Удаление обнуляет gain быстро и снимает данные/ноты канала. Tone.Draw только публикует UI, REC не зависит от rAF.

## REC

Одна транзакция резервирует свободный слот и интервал [start, start+64). На start фиксируются preset/FILTER живого голоса. Open event позволяет записать удерживаемую до REC ноту без её повторной атаки в аудио. Каждая следующая live-атака закрывает прежнее событие и открывает новое, live-release закрывает его. Tick relative, duration в ticks; конец интервала закрывает последний held event.

На end кандидат проходит validClip: 1–64 событий, до пяти конечных MIDI-нот в допустимом диапазоне, позиции/длительности на сетке, всё внутри 3072 ticks. Успех создаёт новую дорожку со своим id, фиксированными нотами/settings, enabled, volume и origin=end. Она начинает повторение на этой точной границе. Live не освобождается: пользователь явно выбрал продолжение удержания поверх лупа.

Пустой кандидат не занимает слот и показывает ошибку. STOP/ошибка/фон отменяют кандидата, сохраняя готовые слоты. Нет перезаписи существующего clip. Пять занятых слотов блокируют REC; deletion освобождает индекс. Каждый новый loop содержит только live-события, никогда предыдущие loops.

## Аудиограф

Сессия заранее создаёт шесть одинаковых PolySynth-контейнеров: live, loop0..loop4. Каждый: PolySynth → lowpass → channel Gain → session gate → master Gain → destination. Тембры — реальные Tone Synth presets SOFT/GLASS/ANALOG/BASS; сэмпловые банки не имитируются. PolySynth maxPolyphony 16 даёт запас на release-переход пятинотного аккорда. Полифония ограничена, новые инструменты на клики не создаются.

На кадре сначала cuts/note-off, затем атаки. Loop duration заканчивается по номеру шага; live sustain держится до release/смены. Preset применяется к каналу только при изменении; каждый loop атакует с собственными сохранёнными settings. Изменение live не меняет loop channels. У каждой дорожки свой gain; master VOL общий. Значения сглаживаются, чтобы избежать резких изменений уровня. Уровни синтезаторов понижены для запаса при пяти loops плюс live.

## Жизненный цикл

Tone.start() только после PLAY/клавиши/пэда. Одновременные gesture-start используют beginStart/generation; поздний async result после STOP не запускает граф. STOP снимает единственное расписание, отменяет Draw/Transport, очищает held input/REC, закрывает session gate за 12 ms. Старый gate никогда не открывается вновь; через 180 ms сессия dispose. Context timeout нужен только для уборки, не для нот.

Готовые slots остаются после STOP, при PLAY их origin становится нулевым. RESET STOP-ит и очищает slots. Закрытие/перезагрузка уничтожает модель; на диск/IndexedDB данные не пишутся. История диагностики ограничена 128 кадрами. Blur освобождает live клавиши; скрытие вкладки/прерывание AudioContext останавливает выступление целиком с сохранением готовых данных.

## UI и проверки

По референсу: верхние BASS/Chord/ARP/Synth, нижняя клавиатура слева, банк loops справа. Pink аппарат с тенями, небольшими техническими подписями. Элементы не перестраиваются на каждом кадре; BPM draft не перезаписывается, announcer REC меняется только при новом состоянии/такте.

Unit tests проверяют гаммы, чёрные аккорды, расширения, arp endpoints, удержания, фактические длительности REC, фиксированные notes/settings, пять slots, STOP/reset, pending BPM и данные. Browser test воспроизводит настоящие пять последовательных записей, проверяет сигнал, клавиши/пэды/ARP, volume/mute/delete, restart, сброс и viewport. Accessibility — контраст/focus. Stress записывает пять настоящих loops, затем проверяет шесть каналов, общий clock, отсутствие клиппинга/роста ресурсов.

Риски: квантованная задержка live, звук пяти конфликтующих тональностей, release/полифония, субъективное качество тембров, Safari/mobile. Тестовый сигнал не доказывает музыкальную выразительность; авторская приёмка остаётся отдельно. MIDI, PCM, постоянное хранение, FX кроме FILTER и sample banks отложены.
